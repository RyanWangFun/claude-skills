## 从零创作流程

适用场景：用户有写作主题，但没有现成内容，需要从零开始创作。

### 工作流程

```
步骤1：主题明确 → 步骤2：素材收集 → 步骤3：大纲构建 →
步骤4：风格确认 → 步骤5：分段写作 → 步骤6：整体润色
```

### 详细步骤

**步骤1：主题明确与目标设定**

提问模板：
```
"让我帮你明确这篇文章的核心要素：

1. 主题：你想写什么？核心观点是什么？
2. 目标读者：谁会读这篇文章？他们的背景如何？
3. 文章目标：希望读者看完后有什么收获或行动？
4. 预期长度：短文（<1000字）/ 中文（1000-3000字）/ 长文（>3000字）
5. 发布平台：公众号 / 博客 / 技术社区 / 其他？"
```

输出：
- 明确的主题陈述
- 目标读者画像
- 核心价值主张

**步骤2：素材收集与整理**

提问模板：
```
"为了丰富文章内容，我需要了解：

1. 你有哪些素材？（个人经历、案例、数据、引用等）
2. 需要我帮你查找补充资料吗？
3. 有哪些必须包含的要点？
4. 有哪些参考文章或竞品内容？"
```

输出：
- 素材清单（按类型分类）
- 核心要点列表
- 参考资料链接

**步骤3：大纲构建**

提供2-3个大纲版本：

版本A：递进式
```
1. 引入：提出问题/现象
2. 分析：为什么会这样
3. 探索：有哪些可能的解决方案
4. 总结：最佳实践和行动建议
```

版本B：并列式
```
1. 引入：主题介绍
2. 要点1：[第一个核心观点]
3. 要点2：[第二个核心观点]
4. 要点3：[第三个核心观点]
5. 总结：回归主题
```

版本C：故事式
```
1. 场景：引人入胜的故事开头
2. 冲突：遇到的问题和挑战
3. 转折：关键洞察或方法
4. 解决：如何克服问题
5. 升华：更深层的思考
```

让用户选择或混合大纲。

**步骤4：风格确认**

提问模板：
```
"这篇文章的风格偏好：

1. 语言：口语化/轻松 vs 书面化/严肃？
2. 节奏：快速直接 vs 徐徐展开？
3. 人称：第一人称（我）vs 第二人称（你）vs 第三人称（客观）？
4. 基调：理性分析 / 感性共鸣 / 幽默风趣？

可以参考你的历史文章风格，或尝试新风格。"
```

可选：读取用户历史文章，提取风格画像（参考 style-guide.md）

**步骤5：分段写作**

按大纲逐段创作：
- 每次完成1-2个段落
- 向用户展示，征求反馈
- 根据反馈调整后续内容
- 保持风格一致性

写作注意事项：
- 开头：吸引读者注意
- 主体：逻辑清晰，论证充分
- 结尾：升华主题，引发行动

**步骤6：整体润色**

完成初稿后进行：
- 结构优化：段落顺序、过渡衔接
- 语言打磨：用词精准、句式优化
- 信息查证：数据、引用准确性
- 格式规范：Markdown、排版

输出最终版本并保存。

## 文章重构流程

适用场景：用户已有完整文章，需要优化改进。

详见 `rewrite-framework.md` 获取完整重构方法论。

### 快速流程

```
步骤1：需求澄清 → 步骤2：原文分析 → 步骤3：多版本重构 →
步骤4：用户选择 → 步骤5：交付成果
```

### 简化提问

```
"让我帮你重构这篇文章，请确认：

1. 结构：是否可以调整章节和段落顺序？
2. 风格：保持原风格 / 尝试新风格 / 看多个版本对比？
3. 内容：哪些必须保持不变？（专业术语、核心数据等）
4. 标题：是否需要优化标题？"
```

## 风格迁移流程

适用场景：用户希望将某篇文章改写成另一种风格，或将某个主题用自己的风格写作。

### 工作流程

```
步骤1：风格识别 → 步骤2：目标风格确认 → 步骤3：内容提取 →
步骤4：风格转换 → 步骤5：质量验证
```

### 详细步骤

**步骤1：源风格识别**

分析原文的6个维度（参考 style-guide.md）：
- 语言特征
- 结构特征
- 叙述特征
- 修辞特征
- 内容特征
- 格式特征

**步骤2：目标风格确认**

选择目标风格来源：

选项A：用户历史文章
```
"我将分析你在 [目录] 下的历史文章，提取你的个人风格。
需要我读取哪些文件？"
```

选项B：指定风格类型
```
"请选择目标风格：
1. 融贯散文式
2. 实用直接式
3. 对话互动式
4. 数据论证式
5. 故事叙述式
6. 清单框架式
详见 style-guide.md 获取各风格的详细说明。"
```

选项C：参考特定文章
```
"请提供1-3篇风格参考文章，我将学习其风格特征。"
```

**步骤3：内容提取**

从原文中提取：
- 核心观点和论证逻辑
- 关键数据和案例
- 必须保留的信息

**步骤4：风格转换**

按目标风格重写内容：
- 调整用词（口语化程度、专业术语）
- 调整句式（句长、复杂度）
- 调整结构（组织方式、段落划分）
- 调整叙述（人称、节奏、基调）

**步骤5：质量验证**

对比检查：
- 内容完整性（核心信息是否保留）
- 风格一致性（6个维度是否匹配目标）
- 可读性（是否流畅自然）

向用户展示原文 vs 转换版，征求反馈。

## 素材整理流程

适用场景：用户收集了大量素材（笔记、文章片段、灵感），需要整理成体系化内容。

### 工作流程

```
步骤1：素材导入 → 步骤2：主题聚类 → 步骤3：观点提炼 →
步骤4：结构设计 → 步骤5：内容组织
```

### 详细步骤

**步骤1：素材导入**

接收素材的方式：
- 用户直接粘贴文本
- 读取指定文件夹下的所有笔记
- 从对话历史中提取关键信息

**步骤2：主题聚类**

分析素材，识别核心主题：

输出格式：
```
识别到以下主题：
1. [主题A]：相关素材 [3条]
2. [主题B]：相关素材 [5条]
3. [主题C]：相关素材 [2条]

建议：
- 主题A和B可以合并为一篇文章
- 主题C素材较少，建议补充或作为独立短文
```

**步骤3：观点提炼**

从每个主题的素材中提炼核心观点：

输出格式：
```
主题：[主题名称]

核心观点：
1. [观点1]
2. [观点2]
3. [观点3]

支撑素材：
- 观点1：[素材A]、[素材B]
- 观点2：[素材C]、[素材D]
- 观点3：[素材E]
```

**步骤4：结构设计**

基于观点设计文章结构：

提供2-3个结构方案：
- 递进式：从浅到深
- 并列式：多个要点平行展开
- 对比式：正反论证

**步骤5：内容组织**

将素材按结构组织成完整文章：
- 每个观点配对相应素材
- 添加过渡和衔接
- 补充缺失的论证
- 删减冗余内容

## 协作创作流程

适用场景：与用户进行多轮互动式创作，共同打磨文章。

### 工作流程

```
循环：草稿 → 反馈 → 修改 → 反馈 → ... → 定稿
```

### 协作模式

**模式A：渐进式创作**

每次完成一小部分，征求反馈后继续：

流程：
1. 写开头（100-200字）→ 用户反馈
2. 写第一部分 → 用户反馈
3. 写第二部分 → 用户反馈
4. ...
5. 整体润色 → 定稿

优点：用户全程参与，方向不跑偏
适用：重要文章、不确定性高的创作

**模式B：大纲先行**

先确定完整大纲，再一次性创作：

流程：
1. 提供3个大纲方案 → 用户选择
2. 细化大纲细节 → 用户确认
3. 按大纲完成全文 → 用户反馈
4. 整体修改 → 定稿

优点：效率高，整体性好
适用：结构清晰的文章、用户需求明确

**模式C：多版本对比**

同时提供多个完整版本，让用户选择或混合：

流程：
1. 理解需求
2. 提供2-3个完整文章版本（不同风格或结构）
3. 用户选择或提出混合方案
4. 基于选择进行优化 → 定稿

优点：用户有选择权，容易找到满意方案
适用：风格不确定、多种可能性的创作

### 反馈处理原则

**理解反馈意图**
- 用户说"不太对"：询问具体是哪里不对
- 用户说"改一下"：明确改什么、怎么改
- 用户说"再好一点"：明确哪个维度（风格/结构/内容）

**快速响应**
- 针对性修改，不大面积重写无关部分
- 保持已被认可的部分不变
- 用对比方式展示修改前后差异

**版本管理**
- 重大修改时保留旧版本
- 用V1、V2标注版本
- 必要时提供版本对比

## 通用流程优化原则

### 1. 始终先澄清需求

不要假设用户意图，通过提问确认：
- 文章目标
- 读者对象
- 风格偏好
- 长度要求
- 必须/禁止的内容

### 2. 提供选择而非决策

不要直接给出唯一答案，而是提供2-3个选项：
- 大纲方案选择
- 风格版本对比
- 标题选项列表

### 3. 渐进式推进

将复杂任务拆解为小步骤：
- 每步完成后征求反馈
- 根据反馈调整后续方向
- 避免大量工作后推倒重来

### 4. 保持透明沟通

告知用户当前进展和下一步：
- "我现在正在分析你的风格..."
- "已完成大纲，接下来将开始正文创作..."
- "检测到风格不匹配，建议调整..."

### 5. 灵活调整流程

根据实际情况跳过或合并步骤：
- 用户需求明确时，可跳过澄清步骤
- 简单任务可合并多个步骤
- 复杂任务可拆分更细

## 场景快速匹配

### 如何选择合适的工作流？

**用户说**："帮我写一篇关于XXX的文章"
→ 使用【从零创作流程】

**用户说**："这篇文章帮我改一下"
→ 使用【文章重构流程】

**用户说**："用我的风格写XXX" / "把这篇文章改成我的风格"
→ 使用【风格迁移流程】

**用户说**："我有一堆笔记，想整理成文章"
→ 使用【素材整理流程】

**用户说**："我们一起写，我想参与过程"
→ 使用【协作创作流程】

### 多流程组合

复杂任务可能需要组合多个流程：

示例1：
```
需求："整理我的笔记，用我的风格写一篇文章"
流程：素材整理流程 + 风格迁移流程
```

示例2：
```
需求："我有个大纲，帮我写正文，写的过程中我要看"
流程：从零创作流程（跳过大纲步骤）+ 协作创作流程
```

示例3：
```
需求："改这篇文章，但我想看不同的改法"
流程：文章重构流程（多版本模式）
```

## 特殊场景处理

### 场景1：用户需求模糊

应对策略：
1. 不要猜测，通过提问澄清
2. 提供场景示例，帮助用户表达
3. 先做小样本，确认方向后继续

### 场景2：用户频繁改需求

应对策略：
1. 每次确认新需求与之前的差异
2. 提示可能影响的内容范围
3. 询问是否需要保留之前版本

### 场景3：素材不足

应对策略：
1. 指出具体缺少什么
2. 建议补充方向
3. 提供可选择：继续（内容较薄）/ 补充后继续

### 场景4：风格不匹配

应对策略：
1. 明确指出哪些维度不匹配
2. 展示目标风格 vs 当前输出的对比
3. 询问是调整输出，还是调整目标风格定义

### 场景5：时间紧迫

应对策略：
1. 提供快速模式：跳过多版本对比，直接输出
2. 牺牲某些维度（如多轮润色）换取速度
3. 明确告知快速模式的权衡
