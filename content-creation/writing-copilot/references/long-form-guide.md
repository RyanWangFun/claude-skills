## 编程式写作的核心原则

### 核心公式

```
人提供原创输入 → AI结构化执行 → 模块化写作 → 风格一致性
```

这个公式的每一环都不可或缺：

**人提供原创输入**
- AI不会凭空创造，它只会结构化你给它的东西
- 你说得越多、输入越丰富，AI产出越有价值
- 没有原创输入，AI写出来的就是「大路货」

**AI结构化执行**
- AI擅长的是把散乱的想法组织成有逻辑的文章
- 你负责想法，AI负责组织——取长补短

**模块化写作**
- 不要让AI一次性生成长文
- 先提纲，再分段，每次只写一小部分
- 这样既能保证质量，又便于把控方向

**风格一致性**
- 内容AI可以生产，但风格是你的
- 始终确保产出符合你的个人风格

### 为什么这样做能去AI味？

「AI味」的本质是什么？

1. **缺乏原创思想**：AI在拼贴已有的内容模式
2. **过于完美流畅**：没有真实写作中的「毛刺」
3. **缺乏个人痕迹**：没有你的习惯用语、思维方式
4. **模板化表达**：「首先...其次...最后...」「总而言之」

编程式写作通过以下方式解决这些问题：
- **原创输入充足** → 解决「缺乏原创思想」
- **模块化写作** → 解决「一次性生成的机械感」
- **风格参考明确** → 解决「缺乏个人痕迹」
- **人工把控方向** → 解决「模板化表达」

## 去AI味的关键

### 关键一：原创输入必须充足

**最好的方式：口述转录**

对着录音工具（通义APP、Plaud录音卡片等），把你想说的都说出来。

- 说得越多越好
- 不用管逻辑、不用管前后是否矛盾
- 重要的是把想法「倒出来」

**为什么口述比打字好？**
- 口述更接近你真实的思维方式
- 口述时更容易说出「真话」
- AI能从口述中提取你的语言习惯

**输入量参考**
- 2000字的文章：口述至少10分钟
- 5000字的文章：口述至少20分钟
- 原则：输入量 > 输出量

### 关键二：风格参考只学风格不学内容

这是最容易出错的地方。

**正确做法**：
```
"这几篇文章是我的风格参考，你只需要学习它们的文风和写作方法，
不要参考其中的任何内容观点。"
```

**错误做法**：
```
直接把参考文章扔进去，不说明用途
→ AI会把参考文章的内容也写进去
```

**风格参考文章的选择**
- 2-3篇即可，不要太多
- 选你自己写得满意的、风格一致的文章
- 最好是近期的（风格稳定）

### 关键三：上下文必须精简

上下文管理是编程式写作的核心技能。

**原则：只放绝对必要的文件**

你的项目文件夹里应该只有：
1. 原创素材（口述转录/笔记/想法）
2. 风格参考（2-3篇）
3. 必要的背景资料

**不要放的内容**：
- 过时的资料
- 「可能有用」的参考
- 相关但不直接使用的内容

**反面案例**：
> 我一开始把AI写作指南1.0和2.0都放进来了。结果AI写出来的提纲，就把这三者混到一起，把过时的观点和我的新观点都写到一起，变成了一个大杂烩。

### 关键四：模块化写作

**绝对不要让AI一次性生成全文**

正确流程：
```
1. 先生成提纲 → 用户确认
2. 按提纲逐段写作 → 每段200-400字
3. 每写完一段，征求反馈
4. 根据反馈调整后续内容
```

**为什么模块化能去AI味？**
- 每次只写一小部分，AI更容易保持风格一致性
- 人可以及时纠偏，防止跑偏
- 分段检查比最后检查更容易发现问题

## 完整工作流程

### 准备阶段

**第一步：创建项目文件夹**

文件夹结构：
```
项目名称/
├── 原创素材/
│   ├── 口述转录.md
│   └── 笔记.md
├── 风格参考/
│   ├── 参考文章1.md
│   └── 参考文章2.md
└── （可选）背景资料/
    └── 相关数据.md
```

**第二步：收集原创输入**

- 口述你的想法（推荐）
- 整理已有的笔记
- 明确核心观点和必须包含的内容

**第三步：选择风格参考**

- 挑选2-3篇你满意的文章
- 确保这些文章风格一致
- 明确告诉AI：只学风格，不学内容

### 执行阶段

**第一步：下达清晰指令**

```
我要写一篇关于【主题】的文章，篇幅大概【字数】，重点讲【核心观点】。

【原创素材文件】是我的口述转录/笔记，本篇文章要重点参考其内容。
【风格参考文件】是风格参考，你只需要参考它们的文风和写作方法，不要使用其内容。

请先读取所有资料，然后生成提纲给我确认。
```

**第二步：确认提纲**

AI会生成提纲，你需要：
- 检查逻辑是否清晰
- 检查是否覆盖了你想表达的要点
- 检查结构是否符合你的预期
- 提出修改意见，直到满意

**第三步：模块化写作**

提纲确认后，让AI按提纲逐段写作：

```
提纲已确认。请按照提纲开始写作。
每次写200-400字，写完一段后暂停，等我确认后再继续。
```

每段写完后：
- 检查内容是否符合预期
- 检查风格是否一致
- 提出修改意见或确认继续

**第四步：整体润色**

全文完成后：
- 检查论述的连贯性
- 确保段落过渡自然
- 校对标点符号
- 最终确认

### 项目配置文件（可复用）

如果经常写作，可以创建一个配置文件，每次复用：

```markdown
# 写作项目配置文件

## 写作流程
1. 先写提纲，再写全文
2. 模块化写作，每次200-400字
3. 每段确认后再继续

## 文风要求
- 标点符号：全部使用中文标点
- 引号：使用「」而非""
- 风格参考文件：只学习文风，不参考内容

## 上下文管理
- 只放绝对必要的文件
- 原创素材是内容来源
- 风格参考是表达方式来源

## 禁止事项
❌ 不要混淆风格参考和内容参考
❌ 不要使用英文标点符号
❌ 不要一次性生成全文
❌ 不要写出模板化的空洞内容
```

## 文风规范

### 标点符号

**必须使用中文标点**：
- 逗号：，（不是 ,）
- 句号：。（不是 .）
- 引号：「」（不是 ""）
- 冒号：：（不是 :）
- 问号：？
- 感叹号：！

**引号特别说明**：
```
✅ 他说：「这个方法很有效。」
❌ 他说："这个方法很有效。"
```

### 表达风格

**追求自然流畅，避免模板化**

```
❌ 「首先，我们需要了解...其次...最后...」
❌ 「总而言之...」
❌ 「综上所述...」
✅ 自然地展开论述，用你自己的方式过渡
```

**要有具体案例和细节**

```
❌ 「这个方法可以提升效率。」
✅ 「用了这个方法后，我每天的有效工作时间从4小时提升到7小时。」
```

**保留个人语言习惯**

- 你的口头禅
- 你习惯的句式
- 你偏好的词汇
- 这些「不完美」正是你的风格

### 结构规范

**标题层级**
- 最多使用3个层级（一级、二级、三级标题）
- 标题要能概括内容
- 避免过于抽象的标题

**段落长度**
- 每段2-5句话为宜
- 避免超长段落
- 同时也避免过于碎片化

**过渡自然**
- 段落之间要有逻辑关联
- 不要突兀地跳转话题
- 可以用过渡句，但不要生硬

## 质量标准

### 完成后自检清单

**内容层面**
- [ ] 核心观点表达清晰
- [ ] 论述充分，有具体案例和细节
- [ ] 逻辑连贯，前后呼应
- [ ] 没有内容错误或矛盾

**风格层面**
- [ ] 读者能一眼看出这是你写的（风格明确）
- [ ] 语言自然，没有模板化表达
- [ ] 保留了你的语言习惯和个人特色
- [ ] 标点符号全部正确

**结构层面**
- [ ] 结构清晰，层级分明
- [ ] 段落过渡自然
- [ ] 开头吸引人，结尾有力
- [ ] 长度符合预期

### AI味检测

**如果文章有以下特征，说明AI味太重**：

1. **过于「正确」和「完整」**
   - 每个论点都有例子支撑
   - 结构完美对称
   - 没有任何「跑题」的内容

2. **模板化表达**
   - 「首先...其次...最后...」
   - 「总而言之」「综上所述」
   - 「值得注意的是」「需要指出的是」

3. **缺乏个人痕迹**
   - 没有你的口头禅
   - 没有你的判断和态度
   - 像是「任何人都能写出来」的内容

4. **过于流畅**
   - 没有任何「卡顿」或「绕路」
   - 真实的写作往往有一些「毛刺」

**解决方法**：
- 增加原创输入
- 强调风格参考
- 手动加入一些「人味」

## 常见问题处理

### Q：AI总是把风格参考的内容也写进去怎么办？

**解决方法**：
1. 在指令中明确强调：「只学风格，不学内容」
2. 把风格参考文件单独放一个文件夹，命名为「风格参考-仅供参考文风」
3. 在提纲阶段就检查，如果有内容混入，立即纠正

### Q：写出来的内容太「AI味」怎么办？

**可能原因**：
1. 原创输入不足
2. 风格参考没有被正确使用
3. AI一次性生成了太长的内容

**解决方法**：
1. 增加口述转录的量
2. 重新强调风格要求
3. 把写作粒度调小（每次只写100-200字）
4. 手动修改一些表达，加入你的「人味」

### Q：提纲和我想的不一样怎么办？

**这是正常的，也是可控的**

提纲阶段是最好的纠偏时机：
1. 明确告诉AI哪里不对
2. 说清楚你想要的结构
3. 让AI重新生成
4. 反复迭代直到满意

**不要在提纲不满意的情况下开始写正文**

### Q：上下文太长导致AI「忘记」前面的内容怎么办？

**解决方法**：
1. 精简上下文，只保留绝对必要的文件
2. 在关键节点重复强调重要要求
3. 必要时开一个新的会话，从提纲重新开始

### Q：如何判断一篇文章是否达到发布标准？

**核心标准：你自己愿意署名发布**

具体检查：
1. 读一遍，感觉像是「你自己写的」吗？
2. 朋友看了，会认出这是你的风格吗？
3. 内容有没有你不认同的观点？
4. 表达有没有你不会用的句式？

如果以上都没问题，可以发布。如果有问题，定位问题，修改后再发。
