# PARA 差异化感知规则

不同 PARA 组件有不同的"引力规则"和涌现模式。

## 01Projects

**结构特征**：自上而下设计，初始化时已确定
**主要感知**：索引偏差、文件职责变化
**涌现频率**：低（结构相对稳定）

感知重点：
- 新文件是否在清单中
- 文件头元信息（input/output/pos）是否准确
- 是否有应该归档的已完成内容

典型信号：
> 这个项目有几个新文件还没被索引。另外，`old-experiment.md` 似乎已经过时了，要归档吗？

## 02Areas

**结构特征**：自下而上生长，持续演化
**主要感知**：聚类涌现、层级深度、边界变化
**涌现频率**：高（需要持续观察）

感知重点：
- 是否有主题聚类正在形成
- 单层文件是否过多（>10 个考虑建子目录）
- 是否有内容应该升级/降级责任级别

典型信号：
> 在「个人助手开发」领域，MCP 相关的内容已经积累了 6 个文件，它们似乎想要成为独立的子区域。

## 03Resources

**结构特征**：最灵活，允许扁平结构
**主要感知**：聚类涌现、升级信号
**涌现频率**：中等

感知重点：
- 是否有主题足够成熟，可以升级为 Area
- 松散文件的主题归属
- 允许比 Areas 更扁平的结构

典型信号：
> 「AI技术」资源下的 Agent 相关内容已经很丰富了，也许可以考虑在 02Areas 建立一个专门的 Agent 领域？

## 04Archives

**结构特征**：冷存储，很少变化
**主要感知**：只关注顶层索引
**涌现频率**：极低

感知重点：
- 顶层索引是否准确
- 不做深层语义分析
- 不建议结构重组

## 通用排除规则

扫描时排除以下目录/文件：
- `.DS_Store`
- `node_modules`
- `.git`
- `.claude`
- `.agent`
- `venv`
- `attachments`（除非已被索引）
- 临时文件、日志文件、缓存文件
