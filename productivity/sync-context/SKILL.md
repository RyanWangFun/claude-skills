# Sync Context

Context 生态系统的感知器官。

## 设计哲学

结构不是被设计的，而是从文件之间的"引力"中涌现的。AI 的角色是感知者——观察隐性联系，识别正在形成的团块，向人类报告。人类确认后，涌现才实例化为文件夹结构。

## 感知能力

### 1. 索引偏差感知

观察实际文件结构与 CLAUDE.md 索引之间的差异。

执行方式：
1. 扫描目标文件夹的实际内容（排除 `.DS_Store`、`node_modules`、`.git`、`.claude`、`.agent`、`venv`、`attachments`）
2. 读取该文件夹的 CLAUDE.md
3. 对比文件清单与实际文件
4. 报告差异

涌现信号示例：
> 这个文件夹里多了 3 个新文件，但 CLAUDE.md 还不知道它们。要我更新索引吗？

### 2. 聚类涌现感知

观察文件之间的主题相似性，识别正在形成的团块。

执行方式：
1. 读取文件夹内各文件的内容摘要（标题、前 500 字）
2. 分析主题分布
3. 识别高密度聚类

涌现信号示例：
> 我发现 `agent-design.md`、`agent-patterns.md`、`agent-tools.md` 主题非常接近，它们似乎想要聚在一起，形成一个 `agents/` 子目录。

### 3. 边界模糊感知

观察现有结构的边界是否清晰。

涌现信号示例：
> 这个文件夹的内容跨度有点大——既有工具使用，也有理论思考。也许可以让它们自然分化？

### 4. 层级深度感知

观察结构是否在合适的深度。

涌现信号示例：
> 这个区域有 15 个文件但很扁平，可能有子结构想要涌现。

## 工作流程

```
进入目标区域
    ↓
观察：
  • 实际文件结构
  • CLAUDE.md 索引状态
  • 文件内容的主题分布
    ↓
识别涌现信号（如果有）
    ↓
以自然语言报告观察结果
    ↓
人类确认 → 执行变更，触发分形自维护协议
人类否定 → 记录，继续观察
```

详见 [references/para-sensing-rules.md](references/para-sensing-rules.md)

## 执行变更后

当人类确认涌现建议后：
1. 创建新文件夹（如需要）
2. 移动文件
3. 为新文件夹创建 CLAUDE.md（含分形自维护声明）
4. 更新相关 CLAUDE.md 的文件清单
5. 触发向上传播

## 报告风格

使用自然语言，不使用结构化报告格式。像观察者一样描述发现，而非像工具一样输出检查结果。
